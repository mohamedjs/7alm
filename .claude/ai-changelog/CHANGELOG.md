## 2026-07-26 — Campaign image generation (spec 014): OpenRouter images, stored as public URLs, generated from Telegram or the dashboard
**By:** Claude (Opus 5)
**Summary:** Added AI-generated campaign visuals to the campaign builder shipped earlier the same day. Scope settled with the user across several rounds: from-scratch generation only (no owner-sent photos), OpenRouter only (explicitly not Gemini — one billing relationship), one image per campaign, ad-quality mockups with print-ready UV files ruled out entirely. CTO agent specced it, then backend was built directly and frontend/n8n delegated in parallel.
**Changes:**
- **Verified the OpenRouter contract with a live curl before writing any code.** `POST /api/v1/images` with `{model, prompt}` returns `data[0].b64_json` + `media_type`; `input_references` accepts an https URL for true image editing. Both confirmed 200 against the real account. ~$0.039 per 1024×1024 image. The spec had flagged this contract as documented-but-unobserved with a second candidate request shape recorded — the first shape was right, so the fallback was never needed.
- **The architectural constraint that shapes everything**: image bytes cannot travel back through an n8n agent's tool-result channel. n8n drops binary from tool output outright, and returning base64 as JSON would push ~1.4 MB into the agent's 10-message memory window and destroy the negotiation loop. So generation lives in a Next.js route that calls OpenRouter, uploads to Supabase Storage, and hands n8n back only a short public https URL — which is what the FB/IG/TikTok publish tools, the Telegram preview, and the dashboard all need anyway. An implementer who hasn't read this will try the direct n8n → OpenRouter tool first and lose an afternoon.
- **Two entry points**: `POST /api/n8n/ai-studio/images` (n8n-only) for the Telegram loop, and `POST /api/admin/ai-studio/campaigns/[id]/image` (admin-only) so images can be generated/refined from the dashboard without going back to Telegram — with no prompt it builds one from the campaign's own copy; with a prompt it refines the existing image.
- **Side effect worth knowing**: this unblocks Instagram and TikTok publishing, which the agent has been correctly refusing because both require an image and it is forbidden from inventing a URL. This tool is now the sanctioned source.
- **Telegram**: `Generate FB Post → Has Image? → Send Campaign Photo → Send Reply`. `sendPhoto` takes the public URL directly (no binary anywhere in the workflow) and deliberately carries **no caption** — Telegram caps captions at 1024 chars and a full campaign proposal exceeds it, so it would 400. The system prompt instructs the agent to restate the current image URL in every proposal, otherwise the URL falls out of the 10-message memory window and the agent loses the image it is meant to be refining.
- **Dashboard**: per-campaign image panel via `next/image` (the Supabase host was already in `next.config.ts`). All generate buttons disable while any generation is in flight — a second trigger on the shared RTK Query mutation clobbers the tracked in-flight row and makes the wrong card look idle.
- `ad_campaigns.image_url` (one nullable column — iterations live in n8n's chat memory and as orphaned storage objects; only the approved image is persisted, the same rule the ad copy already follows). A campaign with no image stays legal.
**Files touched:** `docs/migrations/20260726020000_ad_campaigns_image_url.sql`, `src/features/ai-studio/images.service.ts`, `src/features/ai-studio/campaigns.{repository,service}.ts`, `src/app/api/{n8n,admin}/ai-studio/**`, `src/components/admin/ai-studio/CampaignsList.tsx`, `src/features/ai-studio/ai-studio.{api,hooks}.ts`, `src/features/i18n/dictionary.ts`, `automation/telegram-fb-post-workflow.json`, `specs/014-campaign-image-generation/**`
